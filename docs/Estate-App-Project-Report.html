How the app works (Property + Listing + ROI)

1) Guest experience (no login)

  • Open `/` (Home): frontend calls GET /api/listing/home to load featured offers, recent rent, and recent sale listings quickly.
  • Click any property card: opens /listing/:listingId and renders full listing details (images from Cloudinary).
  • Use header search: navigates to `/search?searchTerm=...` and fetches filtered lists.

2) Sign up / Sign in (authorization)

  • Sign in sets a cookie named access_token (JWT, HTTP-only).
  • Backend middleware `verifyToken` reads this cookie and attaches `req.user`.
  • Protected pages/components work only when the token is valid (Profile, Create/Update Listing, Inbox).

3) How you list (create) a property (Owner flow)

  • User fills Create Listing form (title, description, address, beds/baths, rent/sale, offer/discount, etc.).
  • Upload images to Cloudinary:
    • Client sends image to backend upload route.
    • Backend uploads to Cloudinary and returns an image URL.
  • Submit listing: backend runs POST /api/listing/create (requires token) and stores listing with userRef = req.user.id.
  • Search/Home automatically shows the new listing after it’s stored (home uses the fast home endpoint).

4) Update / Delete (security)

  • Backend checks ownership:
    • POST /api/listing/update/:id updates only if req.user.id === listing.userRef.
    • DELETE /api/listing/delete/:id deletes only if req.user.id === listing.userRef.

5) Messaging / Inbox

  • Send message: POST /api/message/send (requires token)
  • Get inbox: GET /api/message/inbox (requires token)
  • Messages can be linked to a listing via listingId, and sender info is populated.

6) Where “ROI” comes in (what this enables for users)

  • Fast browsing and search increases conversion (more views -> more enquiries).
  • Owner-only controls reduce mistakes and protect data integrity.
  • Cloudinary image delivery improves visual quality, which typically improves click-through.
